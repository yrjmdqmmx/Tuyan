# 信息图实际怎样运行

核对日期：2026-10-10。依据当前工作树代码与本地请求拦截测试；本文不代表生产已部署或真实模型质量已通过。

## 旧流程的问题

八个中文选项有语义区别，但粒度不一致：“数据统计图”是整组图型，“方法框架图”偏表达目的，“时间线/路线图”合并了事件与未来计划。旧 Web 把中文类别塞入正文与任务字段，检索器主要收到 diagram/plot，规划与最终绘制可能仅靠中间文本记住类别。旧统计路线还允许主模型自由写 Python，缺少真实数据门禁。原 306 个 PaperBananaBench 案例缺逐图用途授权，不能因可下载就进入新的正式池。

## 当前请求与任务保存

Web 从 `packages/figure-taxonomy` 读取具体图型。大类只能导航；选择保存稳定 ID，界面显示完整路径。请求新增六个字段：

|字段|实际内容|
|---|---|
|figureTypeId|具体图型 ID，例如 workflow、forest|
|figureSpecVersion|2026-10-10.v1，版本不一致先阻断|
|figureVariantIds|所选变体；未实现的数据变体拒绝，不静默忽略|
|figureAnalysis|方法及说明、统计口径、参考偏好|
|figureData|来源、列单位、原始行、明确计算/绘图选项|
|figurePanels|面板标签、子图类型及其独立输入|

网关保留并校验字段，Core 再按服务端注册表生成完整契约，不信任浏览器自己写的规范。任务、getJob、恢复上下文保留六字段和数据核查记录。旧中文别名可解析；无法确定的旧类别保留原始含义，不自动猜测。Web 检查后端分类版本，旧后端不能悄悄退回只传 diagram/plot。

数据最多 10,000 行、图型与数据上下文最多 1 MB；要求来源和数值列单位。类型专属校验包括有限数值、概率范围、区间包含点估计、矩阵重复项/对称性、生存事件编码等。缺少数据、计算口径或专用渲染器时，付费调用前返回具体缺项。

## 自动检索

1. 只进入逐图已核验存储、展示、模型输入和改编用途的案例池，保留图像 hash；人工选图同样受限。
2. 精确图型或明确标注子图得结构基础分 1000；显式兼容结构得 500；同大类或同主题不自动兼容。
3. 同层内结合主题（最多 50）、布局（15）、密度（10）、学科偏好（20）排序。中文主题目前为简单词匹配，不是专业语义检索。
4. Core 只把最强结构层级候选给主模型筛选。存在精确案例时不会拿主题相似的兼容案例替代；精确案例不够允许少用，不凑数。没有合适案例直接空返回。
5. 检索提示词含完整类型契约、原始内容、图注、候选图型/子图、设计借鉴点、不可迁移内容。主模型只能选择合法 ID，不能凭空生成图库 ID。
6. 下载/读取服务端自有原图字节，核对 hash，再按实际识图角色的图片数、字节及去重预算选用。任务记录精确/兼容数量、原因与无匹配状态；Web 展示匹配情况，目标类型始终保持原选择。

PCA 搜索会定位“排序投影图”，该类也含 PCoA、NMDS 等案例；这是同一基础图型的浏览结果，不意味着允许互换分析方法。规划必须以用户指定的方法和坐标含义为准。

## 主模型、视觉模型、生图模型与程序

|阶段|执行者|收到什么|输出/责任|
|---|---|---|---|
|参考筛选|主模型|结构排名、类型契约、主题、图注、参考元数据|选 ID、相关性理由；允许选零张|
|参考识图|能识图的主模型，或辅助视觉模型|实际参考图片、来源、图型、完整请求|主模型直接观察，或辅助模型提供结构化观察；辅助模型不替主模型决定方案|
|内容规划|主模型|原始研究内容、完整类型规范、参考图/观察报告、布局与输出要求|完整、自包含的生成方案，明确证据缺口|
|风格整理（full）|主模型|完整方案及同样的类型限制|补充版式；不能改事实或弱化科学要求|
|PNG 示意绘制|生图模型|完整方案、原始内容、类型合同、约束、适用参考信息|生成画面；角色不负责发明数据或科学结论|
|SVG 示意绘制|主模型，或原生 Recraft 路线|完整上下文、类型规范与既有 SVG 限制；原生路线实际参考图|源码或原生矢量；保留隔壁会话的渲染、版本/hash 评审机制|
|数据绘制|受限 Python worker|服务端固定渲染代码、不可由模型替换的结构化数据、单位/选项|Matplotlib 计算与绘制；基础数值/图元一致性断言，真实 PNG 输出|
|结果评审|主模型决定，辅助视觉按需观察；数据另作程序核查|当前成品、完整原始要求、类型专属检查、当前方案、版本与证据|问题与完整修订方案；不把新版继承为已通过，也不让视觉模型担保数值正确|

这些是角色，不是硬编码型号。实际渠道与型号由用户生成设置决定；未使用的图片路线不要求密钥。例如新数据图即使选 4K，也不调用生图或生图升清。

## 提示词不是一句“遵循惯例”

`figureContract()` 从注册表展开定义、适用/不适用、必需输入、元素、编码规则、易混淆定义、所选变体/方法、子图、原始数据、生成及评审清单。`workflowContext()` 把合同与原始请求独立打包。检索/规划直接附加 `figureStagePrompt()`；PNG、SVG、观察和评审各次构造请求时重新附带合同，因此不依赖上一模型是否复述完整。

可查看 [流程图规划合同](prompt-examples/workflow-planning.txt)、[流程图评审合同](prompt-examples/workflow-review.txt)、[森林图绘制合同](prompt-examples/forest-drawing.txt)、[森林图评审合同](prompt-examples/forest-review.txt)。这些是从实际函数导出的合同片段，不是假装真实模型响应；完整系统提示还包括各阶段角色/JSON 输出协议。

流程图检查分支条件和路径去向；机制图检查证据与作用符号；森林图检查效应尺度、无效线、区间和真实数据。八种排序/关联分析方法有独立要求，PCA 解释率不能套给 NMDS/UMAP。

## 数据图的能力边界

当前 40 种基础图型实际跑过 worker。主模型只能返回 JSON 规划与 `plotStyle`：宽 6–16、高 4–14 英寸、字号 10–20；不能替换数据或写自由 Python。修改了可执行布局参数才能程序重画；要求无法执行时保留原图并报告未完成，不能假装修订成功。数据精修入口拒绝生图模型修改数值。

明确限制：不实现统计分析本身；排序图接收已算好的坐标；ROC/PR 接收已核验曲线点且不编造 AUC/AP；森林图不自动荟萃合并；KM 当前无置信区间/风险表；箱线采用 1.5 IQR；Venn 仅两集合且面积示意；UpSet 2–8 集合、互斥口径；等值线仅完整规则网格；直方图显式 bins；密度图显式带宽。23 种候选数据图、所有尚未实现的数据变体和含数据子图的组合会在生成前阻断。

程序记录数据 hash、schema/单位/类型校验及成图结果。程序能检查编码与输入一致，不能证明用户数据真实、实验设计有效或原始分析无误。真实模型效果、Linux 容器字体和专业标准符合性仍需独立验收。

## 代码入口

- `packages/figure-taxonomy/src/catalog.js`、`specifications.js`：唯一分类与专属规则。
- `packages/figure-taxonomy/src/index.js`、`plot.js`：合同、检索排名、输入门禁、固定渲染器。
- `packages/figure-taxonomy/src/library.js`：图库筛选与许可门禁。
- `apps/paperbanana-api/src/figure-contract.ts`：请求字段/版本/大小/组合门禁、参考字节与 hash。
- `apps/paperbanana-api/runtime/handler.ts`：任务保存、检索、规划、绘制、评审及恢复。
- `packages/api/src/workflow-prompts.ts`：独立完整上下文与角色提示。
- `apps/web/src/components/FigureTypePicker.jsx`、`FigureInputs.jsx`：选择器、数据与方法输入。
- `apps/plot-worker/render_worker.py`：实际 Python 执行、中文字体与像素输出。

公共只读 MCP 的旧 PaperBananaBench manifest 仍是历史知识入口，并非新的正式生成图库；旧记录不代表逐图授权，新任务不能凭旧 ID 绕过许可门禁。
