## 修复范围

- `state_transition`、`workflow` 的普通 SVG 路径：主模型读取原始输入，提取有来源片段的节点与有向边；程序执行布局并生成真实矢量图元和文字。其他具体图型及原生 Recraft 路径保持原有分支。
- 原始关系不会在布局修订时改变。未声明或模糊的关系、超出当前 2–24 节点 / 1–48 连线边界、无法通过本地布局核验时明确停止，不回退为未经约束的自由 SVG。
- 逐版本评审同时检查实际渲染图、完整源码和原始需求，并逐条枚举应有和实际关系。本地几何失败不能被模型的“通过”覆盖。文本到关系的语义推断仍由模型检查，程序检查不等于科学事实认证。
- 混合组合先分配最终面板尺寸，流程子图和数值子图再分别绘制。数值子图由固定程序根据真实输入绘制，统一组装时不改数值或任意移动数值图元。1K / 2K 字号下限分别为 14 / 28 像素。
- 组合总评协议异常时仍保存原始意见、具体错误、当前版本与子图证据。完整 JSON 在 256 KiB 内保存在阶段记录，超过时保存为带 SHA-256 与字节数的 JSON 对象；不截断 JSON，也不把该对象当参考图片。
- 修改后的 SVG 是新版本，必须单独检查。最后一次修改不会继承上一版的通过结论。整体组合的未执行排版建议明确保留为非通过状态。

## 新版生成和评审如何运行

1. 主模型先读取实际参考图片、原始要求、具体图型规范和固定绘制能力，再规划内容。规划建议不能升级为用户原本没有提出的硬性要求。
2. 程序为原文建立绑定任务和面板的片段目录。主模型用准确名称提取节点，并以 `sourceRef` 指向目录条目；程序检查名称、方向、原文依据和唯一性。原文出现两次的同名 End 仍引用同一个实体；不能偷偷拆成两个 End，也不修补或合并模型返回的非法旧结构。
3. 固定矢量编译器按有向关系布局、布线、放置箭头与标签。状态图的初态、双向转换、回边和非终止 Completed 有各自语义。混合图提前确定面板像素尺寸，各子图分别绘制后统一组装；柱形值及其数据 hash 由程序校验。
4. 程序检查几何和可读性，主模型同时看实际 PNG、完整 SVG、原文与当前关系清单。评审引用同一目录，程序保留原始响应、解析后的准确引文和解析轨迹。目录编号有效并不意味着语义正确，仍必须独立核对每条关系。
5. 如只出现可纠正的响应结构错误，提取最多显式纠正一次，评审只使用原有剩余轮次；有实质问题、未知请求状态或存储失败时不以格式错误为由继续。新版本另行评审，最终只读验收不会改图或回写历史状态。

新任务内部保存 `sourceProtocol` v2 快照，任务读取接口返回该可选字段。恢复时校验原文、目录及协议版本；旧的受影响未完成任务须重新提交，避免复用不兼容的已付结果。未改变原生矢量任务的路线或能力。当前固定关系编译仅覆盖普通 SVG 的流程图和状态转移图，不把这两个案例的通过扩称为所有图型通过。
