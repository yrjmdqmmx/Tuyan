## 问题与修改

网页 `ModelPicker.jsx` 按接入渠道、模型厂商、具体型号组织目录，其移动端也逐级切换。小程序此前虽然保留 vendors 状态及分组函数，选择渠道却直接进入 models，WXML 使用“更换渠道 + 全部厂商下拉框”，导致厂商层没有独立呈现。

小程序现改为三个单列页面，顶部显示“① 接入渠道 → ② 模型厂商 → ③ 具体模型”，突出当前步骤并展示当前路径。打开时回显已有渠道、厂商和型号，从渠道层开始；可通过返回按钮逐级退回，也可通过顶部已可达步骤查看原选择。即使只有一个厂商，也必须进入独立厂商页后再选择型号。

渠道由服务端目录经当前角色、区域与格式过滤产生，厂商沿用目录标准化后的 `modelDeveloper/groupRegistryModels`。Kimi 渠道对应月之暗面，观猹等聚合渠道按角色列出多个开发商；某角色只有一个兼容厂商时仍显示该层。换渠道清空不匹配厂商和旧模型列表。搜索只作用于当前渠道、厂商下的型号，不会跳到其他厂商或修改配置。

三个角色共用该组件。浏览、返回、搜索、展开详情均不触发 select；只有选择合法的具体型号才发送 `{provider, modelId}`，并且会再次验证其角色、格式和厂商归属。设置组件仅更新当前编辑角色的草稿，保存后生效、取消还原。原 API Key 申请指南、渠道共享 Key、MiniMax 区域 Key 与观猹账户授权逻辑不变。
