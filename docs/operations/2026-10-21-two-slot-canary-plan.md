## 范围与开关前置条件

首批范围定为当前授权测试的本人账号、TokenDance `qwen3.8-flash` + `seedream-5.0-pro`、PNG、1K、单候选、1 轮评审、不检索、无上传材料。首次窗口最多 30 分钟或 1 组双任务；候选并发恒为 1、单 Core、现有出口及访问约束不变。使用两个全新合成任务，保留所有旧任务与文件。

现有 `PAPERBANANA_MAX_ACTIVE_JOBS` / `PAPERBANANA_MAX_JOBS_PER_OWNER` / `PAPERBANANA_MAX_JOBS_PER_IP` 是全局配置，**不能仅改为 2 就声称只对一个账号灰度**。代码尚无灰度账号白名单或到期机制，这项是上线前的实现门槛，不用外部代理伪造身份或另开 Core 绕过。

需先实现默认关闭的服务端灰度准入：

- 身份仅取 Gateway 认证后传入的 owner，不信任请求体、浏览器标记或普通用户自填 header。白名单留服务器配置，不进入前端或公开指标。
- 普通执行槽仍 1；只给符合账号和任务条件的调用一个额外槽，总上限 2。普通账号 / IP 保持原限制；不能让普通任务借灰度空位并行。允许账号也必须按实际任务类型判定，长材料、SVG、更多候选或其他渠道不获得额外槽。
- 进入、排队转执行、恢复领取均核验；把灰度归属写入可信执行元数据以防绕过。超出灰度数量 / 截止时间后停止新额外槽，已提交请求允许完成并持久化，不强杀或重发。
- 指标只暴露 enabled、有效期、槽位与固定类别计数，不暴露账号列表。未知请求或恢复日志失败时关闭额外准入，保留既有结果，不能自动更换节点补发。

## 发布顺序

1. 先形成仅本次 PNG 提示/指标/测试的可审核提交；只纳入明确文件和 SYNC 条目，不带走当前其他会话 Web 修改。核对当前线上 SHA、五个镜像和待运行任务；若其他会话已发新版，重新建立候选基线，不覆盖或回滚对方发布。
2. 按当前杭州发布门禁发布评审修复，维持 1 槽；双站 health/ready、公开指标隔离、Core 源码/镜像身份和三个 review 计数核验。没有活动任务时切换，使用既有发布锁及 expected_images 保护。文档快照中的旧 SHA 不能直接作为现场值。
3. 单独完成上述白名单 / 到期 / 队列 / 恢复控制与离线用例，再发布默认关闭的灰度能力。必测普通账号无法占额外槽、伪造身份/不符任务类型拒绝、过期已排队任务不获额外槽、跨网关重复提交和未知恢复仍不重发。所有公开默认限制保持 1。
4. 在限定账号完成生产身份与 OSS 最小核验：认证归属、两个新任务保存、刷新恢复、下载字节摘要与图片库归属。按已授权 TokenDance 范围提交一组双任务，并以服务端同时 running、调用时间重叠、两个独立 run/resultId 证明并行。额外模型消费必须单独记录，不能把本次 0.618168 元覆盖未来消费。
5. 本轮固定任务预计规划/出图/评审各一次，共 6 次；最多允许 8 次以容纳原来 1 轮评审内的合法重画，禁止隐藏重评或格式重试。5 元已发生费用观察阈值仅用于停发新请求，不是正在进行请求的硬费用上限。未知结果立即停止额外准入，不重发该请求。
6. 30 分钟 / 一组双任务结束后关闭额外槽，已运行任务自然结束。复核两站及三节点监控、任务与图片摘要、余额和渠道记录，再决定是否扩大；不自动全量 2 槽。

## 验收和停止条件

必须同时具备：两项独立任务确实重叠；每项候选并发 1；评审完成且版本 / 摘要一致（issues_found 是合法评审结果，但不能冒充 passed）；任务、run、Job、图片库对象和下载摘要一一对应；跨账号读拒绝；运行中 / 终态重复提交均无新增渠道调用；未知或检查点失败跨实例恢复不重发；生产既有账号、任务、文件指纹不变；无新的 OOM、持续队列恶化、依赖故障或未解释的节流/延迟退化。

出现未知计费结果、重复传输、归属错误、恢复日志失败、健康失败即停止新增灰度准入，保留请求 ID 和证据、核对渠道记录。CPU 单点峰值不单独判失败，也不能忽略持续资源压力；与开始前同粒度窗口、容器负载及业务延迟比较，不编造容量或吞吐收益。
