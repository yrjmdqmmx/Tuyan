### 保留例外

按照本次保护历史数据的要求，缺失保存时间保持 `savedAt=null` / `expiresAt=null`，不重置为迁移日。已超过期限的历史图片也先保留待核对，保留原时间证据。这 31 张设置 `retentionHold`，不受自动到期或容量回收影响，但实际字节计入配额；空间不足时拒绝新保存，不擅自删除受保护旧图。存储页明确显示保留提示和缺失文件数量。

新图片以及 2 张有可靠、未过期日期的历史文件仍遵循原 100 MB / 30 天规则。查看、下载、改名、重复引用不续期。后续解除历史保留需要单独核对，不提供批量猜测时间或删除入口。

## 迁移方式

- `plan-image-history.ts` 从只读快照构建带内容摘要的计划；核对账号、源任务、文件格式、实际字节、数据库图片与工作区内容摘要。
- `applyHistoricalImages` 先写独立账号对象，再 HEAD 和完整读回校验；按账号事务写图片索引与任务结果指针，最后切换 Gateway 结果读取。重复运行采用同一对象和索引，不重新计时或重复计量。
- 本轮迁移不删除原 OSS 对象、数据库图片或工作区原字节，不删除原任务。原副本保留用于回退，不作为额外逻辑图片重复计量；之后正常生命周期清理及账号注销会同步处理旧 OSS 别名和关联图片文档。账号注销仍独立清理，历史保留不能阻止用户注销。
- 任务正文、输入材料、工作区内容和使用统计不参与迁移。生产执行器要求维护状态、固定计划指纹、任务快照一致、没有运行中任务；先写保护快照，校验迁移前后内容哈希。
- 运维发布器允许三项服务的布尔 `PAPERBANANA_IMAGE_LIBRARY_ENABLED`；仅 Core 允许独立只读观测开关与 64 位十六进制随机凭据。观测凭据不授予任务 / 管理 API 权限，不改模型路由、付费执行器或生产并发限制。

## 恢复边界

开关切换由受保护发布器备份环境文件并执行健康检查；失败时恢复本次配置，保留维护状态及迁移副本。迁移已建立独立图片指针后，不自动回滚整个数据库，也不直接换回不理解图片库契约的旧 Core；需要先暂停写入，核对迁移后新增记录，再按逐条前镜像恢复引用。原 OSS / Mongo 图片副本与迁移前数据库归档保留，不以删除新增副本作为恢复手段。
