## 方案核对与实现选择

1. 原有结果分属 Core OSS 最终生成图片与 Gateway Mongo `workspaceResults`（包含手工 SVG 版本）。单独限制某一条链路会漏算容量。本次统一新结果到 Core 账号图片库，保留既有手工 SVG 流程和 10,000,000 字节的工作区上传限制；直接生成的结果按图片库 100,000,000 字节上限处理。
2. 原任务删除会清理任务前缀文件与工作区结果。新图片对象使用独立账号前缀；删除任务仍移除正文、原材料和执行恢复数据，图片记录不依赖任务存活。旧结果如尚未迁移，仅保留经账号归属核对的最终文件键及最小核对记录，不保留任务正文。
3. `DrawingActivity` 原组件、接口与日 / 周 / 累计视图未重写。其现有口径来自尚保留的生成任务最终结果，历史任务本身被彻底删除时原有统计行为保持不变；**仅图片回收不会删任务结果元信息或减少生成统计**。不会把图片库存量当作累计绘制数量。
4. 100 MB 使用十进制 **100,000,000 字节**；30 天指服务器首次保存成功后 **2,592,000,000 毫秒**。没有新增“最多 100 张”的限制。
5. 容量置换必须短暂同时持有新旧对象，才能避免新图保存失败先损失旧图。正常完成后有效图片总量不超过 100 MB；删除失败时，尚未确认删除的字节继续计入实际占用，界面明确提示，暂停接收新文件并由服务器重试。不会伪报已释放空间。

## 服务端与失败恢复

`apps/paperbanana-api/src/image-library.ts` 管理：

- `paperbanana_image_assets`：不可变账号 ID、内容 ID、格式、经 HEAD 确认的字节数与摘要、首次保存 / 到期时间、状态和引用；回收后仅保留必要元信息。
- `paperbanana_image_owners`：同账号写入栅栏，Mongo snapshot / majority 事务序列化容量决策和注销。
- `paperbanana_image_uploads`：先记录上传尝试，再 PUT（120 秒超时）；确认后原子纳入容量，失败尝试按唯一键补偿。10 分钟结算窗口后，确认删除才移除尝试记录。并发暂存字节也有 100 MB 上限，超出时提示重试。
- `paperbanana_image_legacy_review`：未经可靠迁移的最终文件最小核对记录。它们不被误标为已纳管；有此类记录的账号暂停新保存且不返回不完整容量。
- 新图片确认成功后，事务先标记过期记录，再按保存时间从旧到新循环回收，直至有效总量达标。PUT / 最终元数据提交失败不会提前回收未过期旧图。
- 每 60 秒自动清理，不依赖页面或登录；进程恢复后继续处理持久化记录。逻辑读取在到期时立即拒绝，物理删除通常在下一次清理周期完成；依赖故障期间重试，不声称文件已删除。
- 注销先关闭账号写入，等待迟到上传结算，清理独立账号前缀、待核对最终文件以及图片库记录。任务删除与账号删除使用不同流程。
- 所有图片接口验证当前会话与账号；不可由请求体切换归属。内部 Save 正文仅可信网关获得 14 MiB 解析额度，普通请求仍为原来的限制。

## 历史数据边界

本轮核对了已上线的代码和持久化字段，**没有扫描生产对象或宣称完成实际历史迁移**。

| 数据 | 已有证据 | 处理方式 |
| --- | --- | --- |
| Core `resultImages` 的 OSS 结果 | 通常能从任务取得不可变账号；文件格式与键可识别 | 缺少独立首次保存时间时列入待核对；不使用迁移时间、任务更新时间或可能被覆盖的 OSS mtime 替代 |
| Gateway `workspaceResults` | 账号、首次插入 `createdAt`、文件内容和 size | 校验实际解码字节和内容摘要；同文件合并，保留可靠的最早日期 |
| 归属不明 / 日期缺失或在未来 / 文件不可用 | 不足以确认 | 保留原记录并要求人工核对，不显示为已迁移、不删除 |
| 可靠日期已过期 / 去重后仍超额 / 超大单图 | 可识别但涉及历史清理 | 单独报告并制定经确认的处置，盘点本身不执行删除 |
| 浏览器缓存、上传原材料、中间产物、临时链接 | 不属于最终结果图片库 | 不导入，不用作已保存容量 |
