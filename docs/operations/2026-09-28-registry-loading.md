# v3.8.1 Web 模型能力目录加载状态修复

## 问题与处理

刚进入专业模式时，服务端目录尚未返回，`null` 被转换成路由契约版本 `0`，因此误报后端不支持。读取异常也落入同一个分支。

Web 现在区分 loading / error / ready；只有成功收到有效目录后，才根据对应契约版本展示不支持提示。专业模式与通用 API 弹框共用状态提示；加载使用中性样式，失败提供重试。健康检查失败时重试健康检查，目录失败时仅重新读取目录。30 秒读取超时进入可重试状态；晚到的旧响应和其他后端响应不得覆盖新结果。这里只涉及只读元信息，不触发模型请求。

后台仍按原来的 60 秒周期更新目录，刷新过程中沿用已成功读取的目录；刷新失败清除能力授权。专业模式生成与精修保留提交前阻断，加载与失败给出准确原因，不放宽能力、密钥或收费任务保护。当前角色、型号、草稿及页面内密钥不随重试清空。比例列表为空且目录未就绪时同样展示读取状态。

## 本地验收（发布前记录）

- 587 项 Web 测试通过，Web 构建与 diff 检查通过。
- 新增 10 项回归：健康检查/目录延迟、失败和畸形目录、重试、超时、晚到响应、后端切换、后台刷新失败、专业模式/通用弹框状态、提交阻断。
- Chrome 1440 / 390 / 320px：加载、失败、键盘重试、配置和页面内密钥保留、Escape 焦点恢复、真实不支持提示均通过，无横向溢出或页面异常。以模拟上游及已读取官方后端目录作为样例，未调用付费模型。
- 原有两处以“不存在红字”判定加载完成的测试改为同时等待 loading 结束；旧源码匹配断言由实际请求状态行为测试覆盖。
- 本次仅改 Web，不涉及后端/共享契约，因此不新增 SYNC 条目；不代表小程序原生 UI 已同步，不执行微信发布。版本继续为 v3.8.1。
