# 三地模型渠道线路实测与匹配 · 2026-10-18

图研业务位于杭州。本轮按用户选择只做零模型费用测试，没有读取测试 Key、执行推理、购买资源或更换用户选择的模型。TokenDance 和火山方舟已调整为杭州直连，百炼保持杭州直连；OpenRouter 仍走新加坡，香港列为更快但尚未完成模型验证的候选线路。

## 测量方法与边界

- 北京时间 12:00:30–12:03:13，三台实际云主机及杭州经中转路径共 156 次 HTTP 探测，零传输失败。三地基线各渠道各 7 次，杭州复测各 9 次；杭州经新加坡的三个既有代理渠道各 9 次、经香港的 OpenRouter 9 次。
- 使用相同 curl HTTP/1.1、全新连接、TLS 证书验证、无重试，记录 DNS、TCP、TLS、HTTP 首响应、完整下载耗时和地址；没有使用本机网络代替服务器测速。
- TokenDance 读取公开模型目录，HTTP 200；百炼 / 方舟 / OpenRouter 读取无密钥的模型或密钥状态接口，HTTP 401。401 表示抵达鉴权层，**不代表 Key 有效、模型可调用或推理成功**。
- 以下为 HTTP 首响应时间，包含连接和 TLS 建立；不是模型首 token 时间、tokens/s 或图片生成时间。样本仅覆盖短时窗口，不代表高峰期、长期稳定性或 SLA。
- 156 次定时探测下载总计约 2.33 MB；另读取一次 OpenRouter 公开目录以检查完整 JSON 传输。没有调用 chat/completions、responses 或图片生成接口。

TokenDance、方舟原本由代码强制走新加坡。取消这段绕行后，免费探测的网络首响应分别减少约 450 ms、1,243 ms，约 89% / 95%；不能将这个比例换算为整次生成任务的加速比例。

OpenRouter 的香港候选路径比新加坡约快 154 ms。香港测试使用只允许杭州来源、仅准许转发 `openrouter.ai:443` 的临时 SSH 隧道，TLS 仍由渠道终止，临时授权和私钥已删除；这不是已部署的香港生产代理。新加坡使用既有 WireGuard + Squid，传输实现并不完全相同。

## 模型与线路匹配

| API 渠道与范围 | 当前匹配 | 原因 / 条件 |
| --- | --- | --- |
| TokenDance，所有经 `tokendance.space` 调用的型号和角色 | **已应用杭州直连** | 国内入口稳定更快；不依据模型原厂所在地绕去海外 |
| 百炼，所有经 `dashscope.aliyuncs.com` 调用的型号和角色 | **保持杭州直连** | 原配置已经直连；本轮没有改成国际站，不替换地域 Key 或端点 |
| 方舟，所有经 `ark.cn-beijing.volces.com` 调用的型号和角色 | **已应用杭州直连** | 取消新加坡绕行，仍访问同一北京 API |
| OpenRouter，所有经 `openrouter.ai` 调用的型号 | **保持新加坡；香港为候选** | 元数据香港更快，但具体模型、账号、上游和地区可用性未验证，不能只根据 401 / 目录切换全渠道 |
| 其他渠道 / 下载域名 | 原策略 | 本轮未测试，未新增使用授权或宣称最优线路 |

机器可读规则见 [channel-model-routes.json](channel-model-routes.json)。型号、角色、模型供应方、请求参数、提示词和密钥不变；只选择应用服务器访问 API 的线路。同一模型通过不同聚合渠道可能使用不同上游、版本和服务策略，因此不能把同名模型质量视为相同。

本轮只验证网络传输可达性、短时延迟、完整元数据读取及代码路由行为，**没有得到模型输出质量、真实推理首字时间或吞吐结论**。Key 的 IP 白名单等账号限制也未验证。OpenRouter 的地区与模型限制仍须按账号和模型核对；线路不能用来证明账号具备模型权限。
