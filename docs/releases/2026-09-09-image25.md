## 上线复验发现与修正

首轮后端 `e911b4b07b63c6909281042a18bfaf3ed3446e9c` 部署后服务健康、静态目录匹配，但公网目录中 OpenRouter 两个新型号的 `refineResolutions` 为空，Web/小程序无法选择精修清晰度；适配器的严格精修校验也会拒绝 `auto`。因此没有发布该版本 Web，先完成 PR #186 并重新执行镜像、后端和目录验收。

最终修正只对这两个已核对的型号声明平台原生尺寸：实时目录完全没有 `resolution` 字段时，生成与精修返回 `['auto']`，严格请求允许 auto，但出站仍省略未声明的字段。目录将来提供分辨率描述时按真实声明处理，不覆盖空、未知或类型变化的显式字段，不放开 4K。回归覆盖真实注册表到生成/严格精修处理器、未声明字段省略、非法 4K 拒绝，以及目录参数变化。

首次实现本地 Core 461、Web 361、仓库/共享 41 项测试和小程序 22 个测试文件通过；修正后的 Core 为 462/462，Core 类型检查、构建与目录生成无漂移通过。最终合并 CI 及 Pages 的 Web 测试通过。供应商响应在本地测试中使用测试数据；没有用生产付费出图替代契约校验。
