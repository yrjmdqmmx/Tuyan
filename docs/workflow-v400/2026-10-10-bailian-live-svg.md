## 实测发现及本地修正

1. **百炼识图图片传输。** 旧识图适配把图片数据上传后改为公网 URL，本地存储 URL 无法被百炼访问。现改为传入已校验的实际图片 Data URL，不改所选型号。普通 SVG、图库及辅助观察的图片请求均实测返回成功。官方文档明确支持此方式：[视觉理解](https://help.aliyun.com/zh/model-studio/vision/)。图像生成/编辑的其他端点仍保留各自适配，没有顺带修改。
2. **计划与 SVG 渲染限制没有充分对齐。** 最初两条评审路径都生成了 `<filter>/<feDropShadow>`，被本地渲染器拒绝；未执行视觉评审，也未宣称通过。现将静态渲染限制加入完整任务上下文、风格和生成提示，并要求用平面形状代替不支持的阴影；重测实际可渲染。禁止效果没有被静默删掉。
3. **本地渲染失败误报。** 原错误被外层标成“图示规划/渠道失败”。现记录独立 SVG 渲染阶段，公开代码 `SVG_RENDER_FAILED`，明确已经生成、未完成评审、没有追加模型调用；费用说明保留此前成功生成调用，不能显示为整个任务未调用。
4. **观察报告 JSON 提示不够明确。** 模型将 content/layout/connections 返回为对象，并使用 `visible_evidence/suggested_correction`，与解析契约不一致。现给出完整字段类型和确切键名；真实重测已通过观察报告解析。
5. **真实主模型使用结构化不确定项。** 保留非空字符串，以及完整的 `{item,detail,resolution}` 结构；拒绝空对象、缺字段和空字符串。不确定项不会被删除或转换成通过结论，任何非空不确定项仍阻止通过。

## 实际画面的剩余问题

- 基础主模型直读的零轮 SVG 将两套公式文字放在相同坐标，实际图片有明显重叠。源码和 PNG 均已留档。该任务正确显示“未评审”，不能据任务成功宣称质量通过。
- 直接识图重测的模型判断为通过，但实际图片中箭头距目标框仍有明显间隔。这一布局细节没有被当次模型指出；后续提示已加强箭头端点、目标边界、重复文字和下标核查，但未追加直接模式真实调用验证这一强化的效果。
- 辅助报告/决策仍存在误判：对没有提供参考图时不适用的标识要求作了多余讨论，并对已存在的 Unicode 下标提出兼容性疑虑。主模型保留了问题/不确定项并生成 v2，而不是错误通过。最终 v2 的布局与公式已人工查看，任务状态仍为“已修改，尚未复审”，没有追加模型质量认证。

这些现象说明实际图片确实进入模型，但不能据这一小样本声称科学图质量稳定。思考关闭、单个合成案例和单次输出也是本轮质量结论的边界。
