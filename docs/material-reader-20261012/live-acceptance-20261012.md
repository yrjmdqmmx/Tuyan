## 已发现并修复的调用链问题

1. 模型可能一次返回多个 JSON 对象、把 render 写入 action，或引用上一阶段读取 ID。每阶段现在最多一次明确纠正，仍计入既有 16 次决策预算；无效请求不执行，越权文件/操作立即拒绝。原始错误响应保留为 `protocol_error`，不能靠丢弃失败来宣称通过。
2. 材料协议失败使用 `MATERIAL_READ_FAILED` 和具体原因；模型已经响应时费用状态标为已有调用，不再误报未调用或要求裁剪图片。
3. 精修材料读取上下文补上用户当前 `editInstruction`，使回查材料围绕实际修改要求。
4. 后续实测仍出现长哈希抄写错误：改为 `usedReadIds:["read-1"]`，后端从当前阶段结果映射回权威哈希。无效短编号不能命中旧阶段或其他文件；原有读取审计结构不变。
5. 材料读取阶段明确只核查原始材料，不应因上传列表没有生成后的 SVG 而拒绝完成；实际成图/代码由随后独立评审接收。
6. 实际 Wan PNG 含透明像素，UI 白底显示，而精修最初误传原始透明 PNG。现在仅对服务器同账号/生命周期、结果已声明白底且哈希一致的图研结果，送入与显示一致的白底副本，并记录原图与送模哈希。原 PNG 不修改；用户透明上传不被静默改底色。
