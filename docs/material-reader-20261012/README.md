## 实际流程

1. Web 统一“上传文件”；先检查扩展名、大小、文件结构。私有对象存储保存二进制原件，PDF 只读页数/元数据，Office 验证包结构，不要求上传时全文抽取。成功卡片显示“已保存 · 待读取”。
2. 临时 PUT 与最终原件使用不同 key，防止签名上传链接重放改变原件。任务只提交材料 ID；Core 从用户及账号生命周期记录取得文件名、大小、SHA-256、保存期限。前端上传失败会请求清理临时文件，清理失败仍受 24 小时过期清理约束。
3. `runMaterialAgent` 用现有 `callTextModel` 渠道收发 JSON，按任务选择 overview/search/read/render。每次结果回到主模型后继续决定。明确记录 `application-json-v1`，没有声称调用渠道原生 function calling，也没有把 Codex 插件安装算成产品接入。
4. 可看图主模型直接收到完整页面像素。仅当主模型渠道不支持页面图且已配置 assist 时使用辅助视觉；无法确认图片通路会停止，不静默降为文字。没有新增强制独立视觉配置或 OCR 凭据。
5. 规划、PNG/SVG 每个成图版本的评审、PNG 精修均可再次读原件。PNG 仍由图片模型生成/修改；SVG 仍由主模型生成源码，程序检查/渲染。修改版本重新评审，图库仍只借鉴结构/风格。
6. 完整读取结果单独存储，包含文件/页/工作表/行/单元格、源文件及页面 hash。任务保留阶段、读取 ID、送模文本/页面记录和结论，避免在 Mongo job 文档里重复堆积全文与图片。稳定读取 ID/缓存允许任务重试复用。恢复前再次验证原件可访问且未过期。
7. 上传/替换/移除/失败/恢复不修改四种检索设置；“参考图偏好”仅在自动检索显示。已保存文件可折叠展开重新加入，不要求再次手工抽取。

## 实际支持与限制

| 格式 | 已实现 | 明确限制 |
|---|---|---|
| PDF | 概况、搜索、指定页/页内行范围文字、可选坐标、完整页渲染；扫描页直接看整页 | 无本地 OCR；复杂表格是原始文字/坐标与画面，不冒充精确结构化表格；文字顺序需结合画面 |
| PPTX | 页码、文字、表格、图片来源、独立备注、图表保存缓存、嵌入 XLSX 原值；整页转换渲染 | 转换可能字体替换/布局差异；逐页文字覆盖和页数检查不能证明所有几何布局保真；嵌入工作簿当前只读前 100 行并明确标记范围 |
| DOCX | 保存原件；转换后的页级文字、搜索及整页画面 | 页码属于转换视图，不保证与用户 Word 分页完全一致；不能声称嵌入对象已理解 |
| XLSX | 工作表概况、按行读取单元格、坐标及公式保存缓存、范围搜索 | 不重新计算公式；缺缓存明确标记；日期可能是序列值；不支持工作表整页画面、图表与样式理解 |
| TXT/MD/CSV/TSV/JSON | UTF-8 原件、行范围读取与搜索 | JSON 在读取时校验；二进制/非法编码读取失败；不截断后继续 |
| PNG/JPG/WebP/SVG | 保持原有图片上传与模型理解通路 | 原有图片协议/尺寸和渠道能力限制仍适用 |
| PPT、DOC、其他未列格式 | 拒绝 | PPT 提示另存为 PPTX；未宣称旧 PPT 转换支持 |

加密/损坏、宏/ActiveX、外部 Office 关系（包括普通外链）被拒绝。动画仅静态页；音视频不播放；公式对象主要依赖页面；OLE 内容未读取且拒绝整页转换。页面中未读取的内容、部分读取、失败均保留说明。整页视觉数值不冒充图表/单元格原值。

文档最多每任务 8 份、每份 10 MiB；每账号最多 50 份保存/待上传文件。ZIP 展开 40 MiB/4,000 项；PDF/PPTX 最多 300 页；一次最多 3 页、24,000 字符，不截断；每阶段最多 16 次模型决策、80,000 字符新读取文本、12 张页面。每文件最多 64 条读取记录/100 MiB 读取缓存阈值。多个模型读回合会增加调用时间与费用，真实成本尚未测量。

原件与完整读取缓存保存 30 天；未完成上传 24 小时。到期立即禁止 API 回查，后台分批清理。下载链接短期有效（300 秒）。移出输入不删除原件；“删除原件”删除原件和完整读取缓存，正在运行的引用任务会阻止删除。已有成图和任务来源说明保留；删除任务记录本身不延长/改变原件期限。账号注销覆盖原件前缀和读取元数据。新账号即使相同邮箱也不能访问旧账号原件。

## 方案选择与运行依赖

[PDF Reader MCP](https://github.com/shuji-bonji/pdf-reader-mcp) 的范围工具设计可借鉴，但其开发环境文件路径/URL 接口不能直接提供给产品模型；本轮采用当前用户任务 ID 的内部 broker。[PDF.js](https://github.com/mozilla/pdf.js) 5.4.624 负责文字/坐标，[PDFium](https://github.com/hyzyla/pdfium) 2.1.13 负责完整页面。没有把内嵌图片提取当作读完整插图。[Docling](https://github.com/docling-project/docling) 保留为复杂布局/OCR 候选；未安装、未集成、未计入能力。

PPTX/DOCX 使用服务端 LibreOffice，`TUYAN_SOFFICE_PATH` 仅允许运维环境指定。随项目的 Noto 字体通过独立 fontconfig 配置进入转换器；已修复真实样本中出现的中文空白，并记录 Calibri 替换提示。Dockerfile 增加 LibreOffice/fontconfig 与实际材料构建 smoke；本机 Docker daemon 未启动，因此 Linux smoke 仍待执行。

解析是固定命令、无业务密钥的独立子进程，60 秒超时/内存/并发上限，Office 禁用宏、拒绝外部关系；模型不能选择 shell、路径或任意 URL。这不是独立禁网容器沙箱，生产隔离和资源配置需要结合 Linux 验收。子进程不会继承模型、数据库和 OSS 密钥。
