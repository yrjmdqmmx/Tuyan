# 浏览器原件与任务临时材料 v2

2026-10-12，本地实现，未提交、推送或部署。此文覆盖 v1 的 30 天服务器保存和分开计算图片/文档额度。

## 当前行为

- 生成候选图：图片与文档合计最多 10 份，每份最大 10,000,000 字节（十进制 10 MB）。精修：待精修原图单独计算，不占辅助文件额度；辅助文件最多 10 份，每份同样最大 10 MB。超限不截取前几份后悄悄继续。
- 文件选择 → IndexedDB 保存原始二进制 → 等待事务提交 → 回读大小和 SHA-256 校验 → 显示“已保存到浏览器”。选择阶段没有材料上传请求。浏览器存储受限、空间不足或回读不一致时不上传；替换失败保留先前原件。
- 提交任务才读取浏览器原件并重新验 SHA-256，上传服务器临时副本。每任务使用新副本；服务器校验格式/大小、归属及不可变 hash，再绑定任务。文件卡片区别本地保存、临时上传失败、待读取、读取成功、部分读取与读取失败。
- 生成与精修辅助材料共用 `MaterialUploadPanel` / `useTaskMaterials`。精修原图也先存浏览器、提交时上传，刷新后可恢复。辅助文件不再要求“参考图用途”等逐文件表单。两页统一使用简短上传说明；去掉独立“已保存的文件”折叠区及空状态，同时移除每个文件卡片的“文件与读取详情”折叠区，仅显示文件名、简洁状态、替换和移除操作；原件与读取记录、刷新恢复及任务复用仍保留。
- 成功、失败或取消后清理该任务的原件、完整读取缓存和 v2 精修输入快照。成图、任务配置、文件来源/hash 与读取审计仍保留；这些不替代原件。删除失败标记 `materialCleanup:pending`，5 分钟清理器重试，成功为 `cleared`。未提交或中断上传最长 24 小时兜底；尚有效的签名 PUT 产生的晚到字节还会再次清理。
- 当前浏览器保留原件、草稿与任务读取记录，按 API 地址和账号分开。任务记录恢复时从对应本地原件重新上传。手动删除原件、清除/回收浏览器站点数据或换设备后不能自动恢复；界面明确报缺失，不能拿摘要继续冒充原始材料。没有另设浏览器自动过期天数。
- 继续已失败的原任务时可重建其临时副本，但必须是同一账号生命周期、同一任务、同一文件 ID 与 SHA-256；禁止换材料后复用已付调用。读取记录 ID 稳定。恢复上传留 15 分钟接续窗口，未接续仍会清理。精修源快照按原件再次校验并重建。

## 格式与模型路径

上传文件入口实际接入 PNG/JPG/JPEG/WebP/SVG、TXT/MD/CSV/TSV/JSON、XLSX、DOCX、PDF、PPTX。PPT 仍明确要求另存 PPTX，不声明支持旧二进制 PPT。

PDF/PPTX 的文字、原始数据、备注及完整页面渲染继续使用已接入的产品内部材料工具，见 [原读取实现及真实文件证据](README.md)。图片现在也是按需读取材料：概况不算理解，`render` 返回完整画面。活动 SVG/外部资源被拒绝；超过 1600 像素的材料预览保持完整构图缩放，原始字节不变，输出中注明小字可能难以识别。

PDF.js + PDFium / LibreOffice 的实际页面证据仍有效；PDF Reader MCP 没有作为 Codex 插件冒充产品接入，Docling 未安装或计入支持能力。Office 字体替换/布局差异、动画/OLE/音视频/公式未读等限制见原报告。XLSX 读取单元格原值与公式缓存，尚无工作表整页渲染。未新增强制 OCR 或独立视觉模型配置。

主模型根据绘图任务读取材料；读取工具仍是 `application-json-v1` 兼容协议，不冒称原生 function calling。单次图片容量小的渠道由**同一主模型**先观察一组页面，带来源保存观察，再继续读取其他页面；分批观察有实际送模审计，观察文本不冒称原始数值，相关原件在整个任务内仍可回查。预算仍为每阶段最多 16 次读取决策、80,000 文字字符、12 幅页面图；不足时明确停止，不伪称完整理解。

PNG 仍为主模型规划、生图模型绘制/修改；SVG 仍为主模型源码绘图/修改、程序渲染检查。数据文件不会触发程序绘图。原图与成图按既有版本评审。文件增删/替换、保存/读取失败与 none/auto/random/manual 四模式独立；参考图偏好仅 auto 展示。

## 接口及持久化

`materialFileVersion:2`、`materialStorage:browser-original-task-temporary`、`materialMaxCount:10`、`materialMaxBytes:10000000`。`materialRetentionDays:1` 是孤立临时副本兜底，不是结束后的保留期限。

上传描述新增 `clientFileId`；恢复上传使用 `restoreId/jobId`，服务端查原任务权威来源与 hash。新精修源使用 `sourceImageUpload.materialId`，由 Core 解析私有对象与校验像素，任务返回 `taskSourceMaterial`。旧 objectKey 路径只兼容旧客户端，不用于新版 Web 文件入口。任务正常完成和失败路径都接入清理，清理错误不把已有成功成图误标为生成失败。

共享契约已记入 SYNC；同步脚本新增 `--skip-miniprogram`。小程序和其他端未同步、未验收；当前 Web v2 在旧 Core 上阻止新材料任务提交。
