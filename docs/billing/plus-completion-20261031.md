## 已确认的商品及退款规则

- 一次购买一个日历月，以核实后的平台起止时间为准；每周期一次 2000 积分。到期失效、不结转；有效期内不重复购买，到期手动续购，不自动续费。
- 确认任务后预留最大积分，同一账户最多 1 个未结任务；候选数、评审轮数影响预留。正式预留表和积分换算仍需确定，不使用模拟扣分表收费。
- 成功或失败都以已确认的供应商实际计费用量结算。文本包含计费输入、缓存与输出 token；图片按供应商实际图片用量单位处理，不能全称为文字 token。释放未使用预留；缺凭证、结果未知、超时保留预留，查询原操作，不重发模型请求。
- 有效期内按 `未用积分 / 2000 × 39 元` 退款，四舍五入到分。先结清全部待核对任务（含旧周期）；申请后暂停新任务；收到已退款证据后结束本周期、收回余分。重复申请返回同一请求，不重复扣回。
- 平台未公布可用退款 API；首版准备人工核实/处理与账本登记，不伪造自动退款。若平台/支付渠道不退手续费，按比例退款仍可能产生小额亏损，需取得费率后计入成本，不擅自从退款额另扣。

## 责任与流程

爱猹收负责收款及时长权益证据；图研负责登录身份、购买入口状态、周期积分、任务预留、用量结算与退款记录。平台 quota/consume 完全不参与，避免两套积分重复扣减。公开文档没有订单查询、取消、退款、通知验签接口，现有代码没有编造这些接口。

1. 登录用户查询 `access`；获得可信沙箱购买链接才显示入口。持久化“购买待确认”，避免用户在外部付款未确认时删除账户。
2. 后端核实权益后，以用户、环境和周期起点生成唯一周期，事务发放一次 2000 积分。回跳参数不代表付款成功。
3. 工作台选 Plus 和三档，提交材料仍走既有所有权检查。报价绑定身份、周期、任务/runId、完整请求摘要、价格版本；用户明确确认最大预留。
4. 网关事务预留、保存固定计价快照；只调用一次 Core。浏览器 API Key、模型路由、用量与预算声明不授予套餐权限。
5. Core 每次供应商传输前做固定模型/接口校验、输入/图片/输出上界和累计预算检查，持久化调用认领。带相同调用标识的请求不重放。密钥仅服务端。
6. 通过原操作键恢复任务，核对供应商 requestId、阶段 ID 和完整用量清单。结算固定提交时的价格；缺证据保留预留并进入人工队列。
7. 确认尚未发送的操作可以取消并释放；已经发出或不确定的不释放、不重扣。取消确认弹窗不产生积分消费。
8. 支付周期异常冻结余额；同一起点的已知 62 天异常收到合格修正可保留原余额恢复，不再次发放。其他突然变化需人工证据。27–32 天仅是异常筛查，**不代替平台对时区、月末规则的正式说明**。

会员有效/异常、退款中、任务未结、购买待确认时阻止永久删除账号。账本不自动 TTL 删除；论文和提示词不存进财务用量凭证。财务记录的正式保留期限与隐私条款仍需发布前确定。

## 固定模型与能力边界

PNG：快速 `qwen3.8-flash`，思考上限 1024；均衡 `qwen3.8-max-0902`，1024；极致同 Max，4096。规划、资料理解、修改指令、视觉评审统一使用该档主模型。图片生成/修改为 `qwen-image-3.0-pro`。

SVG 各阶段上限（资料/规划/代码/观察/评审）：快速 512/1024/1024/512/512；均衡 1024/2048/4096/512/1024；极致 1024/4096/8192/1024/2048。上限不是每次固定用量。

清晰度、画幅、候选与评审仍可调。当前图研百炼图片适配为 1K/2K、单图调用；每次传输固定 `n=1`、`watermark=false`、`prompt_extend=true`，不固定随机 seed。生成候选 1–6、评审 1–5；图片版本修改 1 候选。当前适配尚不接受蒙版/结构图/额外多参考图的 Plus 编辑组合，应明确拒绝，不静默丢弃。此为图研当前适配边界，不等于百炼模型官方能力上限。

## 配置、索引和人工核对

- 网关模板：`apps/auth-gateway/plus.env.example`。默认 `PLUS_ENABLED=false`、新购买/新任务 false、执行 disabled、模型开关 false。
- 价格模板：`docs/billing/plus-pricing.template.json`。所有金额、换算及预算空置，validated=false，程序会拒绝启用。单位 `priceMicros` 是百万分之一元/`perUnits`；`creditCostMicros` 是每积分对应模型成本；整数计算并在整任务最终向上取整，避免按阶段重复舍入。
- 正式任务上限、输入字节上界、图片输入 token 上界、最大输出及费率必须经官方资料和授权测试核实，再复制到仓库外私有文件。`test-support/plus-fixture.mjs` 完全虚构，不得用作正式价格。
- 准备态 managed 还要求服务端 `PLUS_BAILIAN_API_KEY`、`PLUS_PRICING_FILE` 和显式模型开关；Core 独立 `PAPERBANANA_PLUS_PREPARED=true` 才声明协议能力。**本轮均未启用真实模型。** 生产和 live payment 仍有硬阻断，不能只翻环境变量收费。
- 后台核对：`PLUS_BACKGROUND_RECONCILIATION_ENABLED=false` 默认关闭。准备代码每轮最多核对 5 个原任务和 5 个未确认购买，正常至少间隔 30 秒、失败 5 分钟退避；只查询原操作并结算；超过 5 分钟且仍未被认领的预留通过原子取消释放，一旦可能已发出则不释放，不生成新模型请求。上线前确认供应商查询限制并启用监控。已用隔离 Mongo 验证关闭浏览器也能发放与结算；未接入真实平台定时运行。
- Web：`VITE_PLUS_PREPARATION_UI=false` 为默认；只在隔离预览显式打开。
- Gateway 索引计划见 `scripts/plus-indexes.mjs`，默认只输出计划；Core 使用 `paperbanana_plus_budgets` / `paperbanana_plus_calls`，调用与操作唯一键防重。财务集合没有 TTL；仅请求限流窗口可 TTL。生产未执行迁移。

- 核对输入必含 `userId, action, actor, evidenceId`。`settle` 只能用独立确认未计费，或带供应商账单凭证的完整 calls；`refund_confirmed` 要求同周期同金额且确认钱已退；`period_confirmed` 要求同起点、有效月度起止及平台证据；`checkout_clear` 必须确认所有历史购买链接都未付款且已失效。不能把本地改状态当成实际退款或取消支付。
