## 请求能力按渠道处理

- OpenAI：Images API generation / edit 使用模型页的精确 ID。按[生成指南](https://developers.openai.com/api/docs/guides/image-generation)和[编辑 API](https://developers.openai.com/api/reference/resources/images/methods/edit)，开放 1K/2K/4K 中符合 16 像素对齐、最长边 3840、比例不超过 3:1、总像素 655360–8294400 的组合；超过 2560×1440 属于实验尺寸。现有适配器发送 `quality:high`、PNG，省略新型号不支持的 `input_fidelity`。平台最多 16 张参考图，图研当前仍限定一张。
- fal：生成与编辑分别使用 `/text-to-image` 和 `/edit`，编辑来源放入 `image_urls`。[Sunburst 编辑 schema](https://fal.ai/models/openai/gpt-image-2.5/sunburst/edit/api)和[Flare 编辑 schema](https://fal.ai/models/openai/gpt-image-2.5/flare/edit/api)均独立抓取。`image_size` 使用对象，按本渠道明确公布且与既有 GPT Image 2 profile 数值相同的约束校验。只请求一张 PNG，队列查询使用 `openai/gpt-image-2.5/requests/...` 应用根路径。
- Replicate：使用官方 versionless model prediction API，生成/编辑共用型号，编辑传 `input_images`；请求一张 PNG，沿用平台默认质量。本次开放七种比例和自动尺寸。schema 还列出十个显式像素字符串，本轮没有扩展这些额外选择，也没有把 OpenAI 的任意像素规则套到该渠道。不需要或转发额外的 OpenAI 原厂 Key。
- OpenRouter：两个实时模型条目声明比例、质量、参考图等参数，没有声明 `resolution` 或 `output_format`；不会发送未声明字段。已核对两条 endpoint 的 provider 是 OpenAI，以官方默认 PNG 文档建立精确型号 profile，继续执行运行时图像字节校验。该 profile 不是付费实测记录；未知且无格式依据的其他型号仍保留原拒绝策略。

官方 schema 已收入 `config/model-channel-schemas.json`，仅保留接口结构与约束，供独立参数校验。质量档位的官方扩展不在本轮增加用户设置的范围内。
