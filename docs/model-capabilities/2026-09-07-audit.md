## 缺口与实施顺序

1. 图片比例：Qwen/Wan 自定义像素选项不完整，最小像素与生成/编辑上限混用；Ark 只有自动或 16:9；Gemini 遗漏 4:5/5:4；Kolors 遗漏 1:2。需要逐型号尺寸契约、固定枚举、分辨率关联选项及请求级边界测试。
2. 渠道：核对并接入 BFL、Stability AI、Ideogram、MiniMax、Mistral、Together AI、Fireworks、fal、Replicate。不同渠道使用不同模型 ID 和能力；需要独立鉴权、响应、错误和异步适配。无公开可验证协议的功能不开放。

## 尺寸实现

`config/image-size-contracts.json` 为逐型号核对表，记录生成/编辑 profile、来源和日期。`packages/types/src/image-size-contract.ts` 是纯解析器，由目录脚本内联到自包含后端，避免 Laf 跨目录依赖。两端静态目录来自同一生成过程；运行时目录仍为权威。

自定义尺寸先约分比例（包括 19.5:9），求满足最小边、最大边、面积和对齐的整数尺寸区间，再在区间内选择尺寸。不使用单一 1K/2K/4K 宽高假设：Qwen/Wan/Ark 的自定义档位以目标面积计算，GPT Image 2 保留现有目标长边。固定枚举保留官方像素值，即使其比例标签是近似值。

Ark 官方当前支持自定义像素：4.5/5.0 lite 至少 3686400 像素，旧 2048×1152 无效；5.0 pro 下限 921600、上限 4624220。自动模式继续传原生档位。Qwen3 的最小面积为 262144，最大为 4194304；Wan2.7 Pro 生成最高 16777216，编辑最高 4194304。

Recraft imageToImage 和硅基流动 Qwen Edit 不接受目标尺寸，精修只提供“原生尺寸”。Recraft 的分析后重绘仍走生成契约。Kling 保留官方三种比例。Vidu 保留分型号的完整像素表。硅基流动 Qwen 官方表为 1472×1140（标签 4:3），不擅自改成原厂尺寸。硅基流动 ERNIE/Z-Image 的公开接口未列完整自定义边界，目前保留已登记的 1024×1024，未继承原厂能力。

OpenRouter 继续读取本渠道声明的参数；未声明的比例不推断为原厂支持。型号和源图能力以渠道目录为准。官方资料未声明的硬限制不冒称官方规则；自定义候选比例还受产品的 16384 边长/20 MP 解码边界约束。

## 审计中未开放的能力

- MiniMax `subject_reference` 是人物特征参考，不等同于任意科研图编辑；`image-01` 精修使用视觉分析后重绘。
- Fireworks 旧图片生成 API 文档当前返回 404，现行文档可确认 Kimi K2.5 文本/视觉；本轮未加入失效的图片 workflow。
- fal 编辑 schema 的范围比生成声明宽，暂开放能满足生成端约束的保守子集；Together 的尺寸不继承 BFL。精修多源图仍沿用图研当前单源图产品流程。
- Seedream 5 Pro 的原生 1.5K、5 Lite 的原生 3K 未新增为产品档位；已在现有 1K/2K/4K 档位范围开放合法自定义比例。硅基流动未公开完整边界的型号保持保守选项。
- OpenRouter 沿用动态参数 schema 和本渠道生命周期；不将原厂尺寸能力复制到聚合路线，不将静态目录数量当作 OpenRouter 动态数量。

## 客户端与任务入口

Web 与小程序按“型号 × 生成/编辑 × 分辨率”决定可选比例；切换分辨率会清除不再合法的固定比例。38 个候选比例并非每个模型都能选择。后端在入队、账号读取、密钥检查前拒绝不合法的静态图片尺寸组合；普通生图返回 `IMAGE_SIZE_UNSUPPORTED`，精修返回 `REFINE_IMAGE_SIZE_UNSUPPORTED`。已有比例/分辨率错误码保留。`512` 和 `auto` 从精修入口完整透传到请求；自动增强严格检查编辑尺寸，不再静默降档。
