## MiniMax 统一入口

界面、provider ID 和适配器保持一个入口：**MiniMax / `minimax`**。区域选择位于入口的接入凭据中：

| 区域值 | 官方 API Base | Key 来源 | 可用图片型号 |
|---|---|---|---|
| `global` | `https://api.minimax.io/v1` | `platform.minimax.io` 当前账号 | `image-01` |
| `cn` | `https://api.minimax.cn/v1` | `platform.minimaxi.com` 当前账号 | `image-01`、`image-01-live` |

文本接口统一使用 Chat Completions、Bearer 鉴权和 `reasoning_split:true`；图片使用 `/image_generation`，校验业务状态后读取 base64 结果。两区均纳入官方当前列出的 M3、M2.7、M2.7-highspeed、M2.5、M2.5-highspeed、M2.1、M2.1-highspeed、M2 八个文本型号；M3 单独拥有视觉能力。

`image-01` 可用宽高 512–2048、8 像素对齐的自定义尺寸。`image-01-live` 仅中国区，按七个固定比例请求，不发送 width/height，不开放 21:9。人物参考接口不等于通用图像编辑，两个型号的科研精修通过分析后重绘完成。

`providerRegions` 随创建、精修、输入优化、路由快照和任务记录传递。客户端只在页面内存维护 `minimax:global` / `minimax:cn` 分区 Key；请求中只出现所选区域的 `apiKeys.minimax`。旧的无区域 Key 仅兼容国际区，切到中国区不会沿用。后端声明 `providerRegionContractVersion:1`，旧服务端无法识别中国区域时客户端阻止提交。中国接口保持直接出站，国际接口遵守 SG 出口配置。

依据：[国内 Chat API](https://platform.minimaxi.com/docs/api-reference/text-openai-api)、[国际 Chat API](https://platform.minimax.io/docs/api-reference/text-openai-api)、[国内图片 API](https://platform.minimaxi.com/docs/api-reference/image-generation-t2i)、[国际图片 API](https://platform.minimax.io/docs/api-reference/image-generation-t2i)。

## 比例、尺寸与实际请求

共享解析器先按具体型号、渠道、生成/编辑和分辨率选择约束，再解析比例和像素。候选比例池为 45 种；某个型号只开放其官方固定枚举，或能在自定义尺寸约束内构造出的组合。生成器生成 `aspectRatiosByResolution` 和 `refineAspectRatiosByResolution`，Web、小程序与后端共同使用这一结果。入队前和调用前均验证，禁止通过手工 API 请求绕过限制。

- 同时约束宽高上下限、总像素、最大宽高比、像素对齐以及分辨率档位。档位代表请求目标，固定原生尺寸和面积限制下的实际像素以对应契约为准；不把所有型号的 2K/4K 当成同一个正方形尺寸。
- OpenAI GPT Image 2、MiniMax Image-01、BFL、部分 fal/Replicate 路线采用合法自定义像素；固定尺寸的旧 GPT Image、Ideogram 和 Qwen 旧生成型号保留各自原生枚举。
- Seedream 4.5/5 Lite 的最小总像素不能从 Seedream 4.0 复制；fal、Replicate、Ark 的同名系列也不互用尺寸限制。fal Seedream 5 Pro 仅按其 1–4 MP 契约。
- 旧百炼 Qwen Image 生成仅开放五个官方原生尺寸；旧编辑 Max/Plus 每边 512–2048，旧基础编辑不发送不支持的 size。
- Recraft 直接编辑、Stability SD3.5 图生图、部分 Replicate 源图模式继承源图大小；这些编辑路径只提供原生/自动选项。
- Together 多数新图像型号未公开渠道内精确自定义尺寸限制，暂仅提供平台默认尺寸，不借用原厂或其他平台的尺寸。此限制在逐型号记录中列明；可用的默认请求仍已适配并模拟验证。
- 直接编辑目前使用一张源图；`maxReferenceImages` 表示图研实际发送上限，`providerMaxReferenceImages` 单独表示文档明确给出的厂商上限。文本规划/识图维持最多三张、单张 5 MB 的产品约束。不把人物参考、遮罩必需或风格训练接口标为通用编辑。
- 栅格输出按实际字节验证并规范化为 PNG；支持的原生 Recraft SVG 保留矢量。图片大小最多 20 MP，最大边 16384，覆盖本次合法的超宽比例并限制解码内存。

## 调用实现与边界

| 渠道 | 鉴权 / 请求 / 响应 |
|---|---|
| OpenAI、xAI | Bearer；按型号使用 Chat/Responses 或图片 API；兼容状态、截断和错误不会当成完成文本。 |
| Anthropic | x-api-key、anthropic-version；原生 Messages 与 base64 参考图。 |
| Gemini | Google API Key；GenerateContent/Interactions 按现有具体路由。 |
| 百炼、Ark、DeepSeek、Kimi、智谱、SiliconFlow、MiniMax、Mistral、Together、Fireworks | 各自官方域名的 Bearer 请求；Omni 单独处理 text-only SSE，图片按原生 JSON/multipart 或独立任务接口，不把“OpenAI 兼容”当成图片协议。 |
| BFL | x-key；一次提交，按返回的官方区域 polling_url 查询，Ready 后无凭据下载。 |
| Ideogram | Api-Key；按具体版本的 multipart 或 image_request JSON 调用。 |
| Stability | Bearer + multipart；检查 finish_reason，SD3.5 使用 mode/model。 |
| fal | Authorization: Key；queue 提交、status、response 分离；使用逐操作 endpoint 和官方字段。 |
| Replicate | Bearer；官方 owner/name predictions 或 version 固定的 predictions；处理字符串、数组和图像对象输出。 |
| OpenRouter | Bearer；文本与 Dedicated Image API 分开，按目录声明的格式、分辨率、比例和引用参数提交。 |

新增异步图片接口提交 POST 不重试，轮询有截止时间；失败、取消、审核、缺失状态、超时和异常输出明确报错。任务 URL 约束在对应官方域名；资产下载不附 API Key。真实账户权限、限流和地区可用性需要后续账户验收。
