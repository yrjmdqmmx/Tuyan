# TokenDance 目录故障隔离（2026-09-19）

## 根因与只读证据

2026-09-19 的公开 `GET https://tokendance.space/gateway/v1/models` 返回 HTTP 200、96 条记录，其中 `deepseek-chat-v3-0324.supported_protocols = null`，其余 95 条为数组，无重复 ID。生产 Core provenance 为 `df2c0b33ad4c3f425eced4c68fbe98cc28c95e5e`，原代码用 `data.some(...)` 判整表无效；图研 `modelRegistry(provider=tokendance)` 返回空 providers 和渠道不可用。主机 Core 最近三小时 / 最多 5000 行日志（实际 1476 行）没有目录类别、模型 ID 或协议异常定位信息；仅 HTTP 成功不代表目录可用。此前容器内只读请求同样复现该条 null。

影响为整个 TokenDance 渠道的目录展示和请求前校验，其他直连渠道不受该条记录影响。Web 原先在渠道消失时自动改选其他渠道，进一步改变了用户设置。无法仅据 null 判断供应商模型已下线、账号无权或余额不足；供应商为何返回 null 尚未确认。

补充当前响应与修复后的真实 Core fixture 核验：图研已审核目录 62 个型号中，60 个协议匹配；除上述 null 型号外，`deepseek-v4-flash-vision-exp` 当前已不在上游目录，单独暂停调用。其余五条含下划线的视频 / 语音协议是合法元数据，不能误判格式异常，也不能据此接入为聊天协议。见同目录 evidence JSON。

## 新契约与处理

- Envelope 必须有数组 `data`（最多 5000 条）。空目录与所有条目无效分别标记；不放宽整个 envelope。
- 单条必须为对象，ID 必须为非空有界标识，`supported_protocols` 必须为非空字符串数组，协议必须符合命名格式。分别记录 missing/null/type/invalid/empty 等原因。
- 同一 ID 出现多次时隔离该 ID 的所有记录，不做先到优先或合并推断；协议重复元素仅去重，不改变语义。
- 其他上游可选展示字段不参与调用协议判断；图研展示及能力仍来自已审核静态目录。新上游型号不会自动接入；格式合法但未支持的协议不会转换为已有协议。
- `catalogHealth.tokendance` 返回 state/cause、上次成功 checkedAt/expiresAt、stale、issueCount、最多 100 条脱敏 issues、usableCount、affectedModels、message、failureCount、alert。`catalogWarnings` 表示部分异常；`unavailableProviders` 表示整个渠道当前不能使用。正常模型不会因为另一条异常而被移除。
- 已审核型号即使异常仍返回原 ID 与 `selectable=false` / `disabledReason`，以保留用户选择；默认 ID 不重写。客户端只展示禁用项，不能提交调用。

## 缓存、调用与恢复

目录展示缓存 60 秒；并发刷新合并；失败退避 10 秒以免刷新风暴。成功时间不会被失败刷新延长。失败时最多保留 15 分钟的旧快照，但明确 stale 并禁用全部 TokenDance 调用；空或全部异常的新目录会替换旧成功快照，不能用旧模型绕过。

每次实际 TokenDance 文本、识图、图像请求发送前，强制只读刷新（仍合并并发与遵守失败退避），按适配器实际发送的协议匹配所选 ID。无图识图阶段不发送请求。目录通过仅代表本次元数据匹配，不保证后续账号权益、额度或供应商生成一定成功。

目录拒绝、限流、超时、网络、供应商 5xx、格式异常与单型号异常使用不同中文原因；均在付费 POST 前停止，标记 `not_sent`，可在目录恢复后手动继续原任务并复用成功步骤。原先已发出但结果未知的调用仍停止自动重放，费用仍未知。此变更不重跑历史任务、不迁移旧执行记录。

## 可观察性

日志事件 `tokendance_catalog_health` 仅含受控类别、HTTP 状态、公共模型 ID、行号、计数、时间、是否陈旧和告警等级；不记录响应正文、描述、请求头、用户、密钥、Cookie 或原异常字符串。单条异常初次 warning，连续三次刷新异常或持续五分钟升级 critical；全目录不可用或已接入型号全部不兼容立即 critical。状态/受影响集合变化立即记录，同状态最多每分钟一条，恢复立即记录 alert=none。只读 `modelRegistry` 同时提供当前诊断，可被现有日志采集或健康巡检读取。

Web 打开时每 60 秒刷新目录；没有访问时不主动轮询供应商，因此这是访问驱动的告警事件，不是独立定时监控服务。外部通知渠道未新增、未发送消息；如需无人访问时监控，应由运维轮询只读目录并对 critical / 恢复事件配置通知。无需调用生成 API。

排查时先查看 catalogHealth 的 cause / affectedModels / checkedAt / stale，再按事件名筛选容器日志；不要导出原始生产日志或环境变量。错误中出现协议变化时，应人工核对供应商协议后再适配，不能临时补成 OpenAI 协议。

## 验证与发布边界

本地单元与真实 Core 组合 fixture 覆盖单条 / 多条 / 全异常、空目录、重复 ID、缺失/空/类型错误、协议变更、刷新合并、超时/网络/拒绝/限流/5xx、缓存过期、供应商恢复、脱敏与告警升级。适配器测试确认正常模型可走 mock transport，异常型号调用次数为零；工作流测试确认恢复保留成功步骤，未知结果不重放。

Web DOM 测试覆盖普通 / 专业模式、目录消失、网络错误、隔离与恢复，断言所选渠道 / 模型及三个输入不变；小程序验证隔离默认项仍显示但提交被拒绝，其他渠道的默认项严格校验保持。

当前记录为发布前验证；精确测试数量、CI、发布版本与线上核验以正式发布记录为准。未进行付费生成、历史任务重试、真实权益或账单核对，未上传微信平台。
