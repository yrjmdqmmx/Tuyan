## 信息结构与行为

- 现有“账号”入口改为“账户”，独立 `?view=account` 页面集中放置图研身份、账号与隐私、观猹 TokenDance 连接、钱包/Key 额度说明、充值和最近 10 笔充值记录。旧 `?tokendance_wallet=1` 链接仍有效。
- 首页、生成设置和精修页移除大块重复钱包，只显示简洁连接状态、已查询余额和账户入口。账户页使用现有纸色/鼠尾草绿设计变量，窄屏为单列；按钮具备统一字号、间距、焦点、禁用及反馈状态。
- 进入账户时保留原工作区组件挂载，记住原页面和滚动位置，返回后保留方法/图注/负向提示、精修指令、模型选择、上传控件和任务详情展开状态。原有任务轮询继续运行；账户访问、充值查询、授权完成均不自动创建或恢复任务。
- Web 自动只读查询余额及近期记录；查询失败保留错误，避免后续查询清除授权失效提示。重新授权沿用原一次性 PKCE 流程，授权弹窗不替换原任务。解除连接增加行内确认。
- 钱包整数微元、充值整数人民币元的契约不变；支付状态确认到账后更新余额，用户显式返回原任务并选择继续。未知创建结果阻止重复创建；记录按订单单独查询。`tokenDancePayments` 新增可选 ISO `createdAt / checkedAt`，旧记录缺日期不编造时间。
- 小程序沿用 `pages/tokendance` 路由，页面标题改为“账户”，增加图研账号、隐私与返回入口、完整充值记录及逐笔查询。顶部和精修入口简化，仍使用系统浏览器授权/支付方式，不改变平台能力边界。

## 渠道与目录 v18

用户可见名称统一为“观猹 TokenDance”。`orderModelChannels` 只将 `tokendance` 稳定置顶，保留其他渠道相对顺序；普通模式和各角色弹窗复用该规则。已有路由及默认模型不因置顶而改变；内部 ID、归因 URL、授权/调用字段和服务端用户 Key 边界保持原契约。

共享排序源为 `config/model-presentation.json` 与 `packages/types/src/model-presentation.ts`，自动生成 Core/Laf、Web、小程序版本。规则：

1. 有官方发布日期的型号按实际日期倒序。
2. 日期缺失时，用经过审阅、附官方来源的同系列版本关系补充约束，不让新版本因日期未知排在旧版本后面。
3. 日期与版本关系采用无环的全序输出；确有冲突时优先官方日期。无法建立先后关系或同日同版本才使用 ID 作为确定性平局规则，防止 API 数组顺序变化导致抖动。ID、推荐标记和选中状态不用于推断发布时间。
4. 未知日期继续为 null，并显示“按官方版本排序”或“发布日期待确认”；卡片与详情使用同一生命周期标签，日期快照另加标记。能力和下架策略仍由渠道契约决定，不把排序当可用性保证。

本轮核对：[TokenDance 实时目录](https://tokendance.space/gateway/v1/models)、精确型号详情及 [DeepSeek 官方更新日志](https://api-docs.deepseek.com/updates/)。补齐 DeepSeek V4.1、TokenDance V3-0324 别名、Seedream 5.0、Qwen Image 2.0/3.0、Seed 2.x、Hunyuan 4/3、Step 3.7/3.5 的系列匹配。

DeepSeek 示例：V4.1 Flash 以渠道所示抢先体验状态标为预览、发布日期未知；V4 Flash Vision Exp（8 月 21 日）、Pro 0813 与 Flash 0731 的稳定快照随后。TokenDance 仍命名为 Preview 的 V4 Pro/Flash 别名使用 4 月 24 日预览日期，不套用官方直连的后续 GA 别名日期；V3.2 和 V3-0324 随后。详情与卡片一致，不编造 V4.1 发布日期。

最终公开 API 再核对时间：2026-09-09 10:37 UTC。仍为 93 个实时型号，无新增/下架/协议/描述或名称差异。集成型号保持 62 个：主模型 60、提示词优化 60、参考图识别 27、生图 2、直接精修 2（角色重叠）。未映射的 31 个型号与原因见 [完整覆盖表](model-coverage.md)。全渠道静态目录仍为 739 个型号，本轮没有扩展音频、视频、向量等产品范围，也没有以收益筛选模型。

刷新机制沿用 15 分钟存活/协议校验；差异检查器本轮增加名称变化提示，避免 Preview/GA 重命名漏审。未经审阅的新型号和能力变化需要更新 canonical catalog 后生成各端，不静默放宽请求能力。
