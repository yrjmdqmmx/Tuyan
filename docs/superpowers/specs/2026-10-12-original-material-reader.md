## 设计

1. 文档先检查后上传私有 OSS，使用服务端随机 ID、用户/账号生命周期归属、内容 hash 与确认状态。客户端任务仅提交 ID；服务端读取权威元数据，不接受任意路径、URL、工具名或用户传入的读取结论。图片保留现有原件上传协议。
2. 新增 materialFiles 可选协议，保留旧 sourceMaterials 文本任务兼容。原件保存 30 天，期限在文件卡片明确显示；移出输入仅影响下一任务，主动删除原件会使历史引用不可再读。未完成上传 24 小时后清理；到期原件及读取缓存由现有清理调度删除，账号注销纳入现有对象清单。文件移出不改变检索配置。
3. 后端操作为 overview、search、read、render。PDF.js 提取指定页带位置的文字；PDFium 渲染完整页面。Office XML 提取 PPTX 文本/表格/图表缓存和嵌入工作簿/备注，LibreOffice 转换后由 PDFium 渲染页面；记录页数、文字覆盖、字体替换检查和转换差异风险。拒绝 PPT、加密包、宏、外部关系及不受支持的活动内容，不伪装成成功。
4. 主模型通过显式 JSON request/response 应用层循环选择文件、页、工作表和操作。当前渠道不宣称原生 function calling；结构不合法或读取预算耗尽时明确停止。原件和读取结果为不可信数据。每次规划及实际成图评审前均可调用；页面直接交可识图主模型，只有主模型不能看图且配置 assist 时使用辅助视觉。每次结果与送模页图保存 hash、来源、阶段及结果记录。
5. 子进程隔离解析，文件/解压/输出/页数/运行时间/并发有上限；渲染进程不接收业务密钥。Office 禁用宏并拒绝外部链接、嵌入可执行对象；仅固定转换命令，模型不可指定 shell。Linux 运行依赖与隔离约束随 Docker 文档交付，未验证不称生产通过。
6. PNG/SVG 路由与实际成图评审保持。图库仅结构/风格，不替代材料事实。原件读取环节与检索四模式独立。

## 分批与验证

- 第一批：原件上传/保存、授权/到期/删除、PDF/PPTX/现有格式读取与真实文件样本。
- 第二批：主模型读取循环、规划/评审接入、共享请求、任务恢复和读取证据。
- 第三批：上传卡片、详情/原件恢复、四模式交互、两种格式模拟链路与实际渲染检查。
- 真实付费验收待用户提供凭据；无凭据不冒充完成。代表样本覆盖普通/双栏/矢量/表格/扫描/混合 PDF、中文 PPTX 文本/图片/形状/表格/图表/备注、损坏/加密/超限、越权和跨任务引用。

## 候选比较

- PDF Reader MCP 0.15.5：提供文本/搜索/整页渲染，采用 PDF.js 与可选 PDFium；直接 MCP 文件路径/URL 接口不符合本产品的用户材料授权边界。借鉴其操作契约，在产品内部实现受限 broker。来源：https://github.com/shuji-bonji/pdf-reader-mcp
- PDF.js：现有 5.4.624，继续用于文字及位置提取；Node 整页画面另外用 PDFium，需以真实样本比较结果。来源：https://github.com/mozilla/pdf.js
- Docling：可处理复杂布局、表格和 OCR，但需另行管理模型下载、CPU/内存和结构推断误差；本轮不把候选能力算作已接入。先用原始文字位置与整页视觉，复杂表格不能将视觉估读称原始结构数据。来源：https://github.com/docling-project/docling
