# PaperBanana Web 移动端主布局居中设计

## 背景

生产移动端截图显示工作台整体向左偏移。根因位于 Web 响应式样式：`≤520px` 时 `.app-shell` 最大宽度限制为 `366px`，同时固定 `margin-left/right: 12px`。当视口宽于 390px 时，容器未占用的额外空间只留在右侧，导致页头、导航、Hero 和后续内容整体不在水平中心。

## 方案

- 保留现有 `366px` 最大宽度和 `24px` 最小水平留白，维持当前移动端内容密度。
- 将该断点下的固定左右边距改为自动水平边距，使 `.app-shell` 作为整体在视口中居中。
- 不逐个修改页头、导航或 Hero，避免重复规则和组件间漂移。
- 不改变桌面布局、组件结构、API 或共享契约。

## 验收标准

- 在 390px 与 430px 移动视口下，`.app-shell` 左右可用空白相等，误差不超过 1 CSS px。
- 页头、标签导航、Hero 与主体内容继续共享同一水平中心线。
- 现有小屏宽度上限、边框、圆角、内容换行和纵向滚动保持不变。
- 相关 Web 回归测试和生产构建通过，浏览器控制台无新增错误或警告。

## 测试策略

1. 先添加一个针对 `≤520px` 响应式规则的失败测试，证明当前固定边距会造成偏移。
2. 最小修改 CSS 后重跑该测试和 Web 全量测试。
3. 启动本地 Web，在 390px、430px 两个视口检查容器边界、页面内容和控制台，并保留修复后截图作为验收证据。

## 发布与回滚

这是纯 Web CSS 修复，不更新 `SYNC.md`。通过 PR 合并后仅需部署 Pages，不部署 Core。若出现回归，回滚本次单一 CSS 提交并重新部署 Pages 即可。
