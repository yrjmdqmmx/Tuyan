# 通用 API 接入首版设计

用户已授权完成首版实现、验证和既有流程发布；不进行付费验证或重跑历史任务。

## 信息结构

最终交互采用「生成设置 → 使用模式」的三个入口：普通模式（平台单渠道）、专业模式（平台预设按角色分配）、通用 API（自有服务按角色分配）。这替代了草案的独立接入方式开关，减少一层嵌套；界面明确模式不是协议，渠道由接入地址表示。普通/专业的原设置独立保留，通用 API 不覆盖它们。通用 API 的每个角色选择一个协议、准确模型 ID 与接入地址，填写密钥。识图/图像角色可主动复用主模型接入；地址或认证协议改变时必须清除该份密钥绑定，保留其他输入和平台预设路线。保存配置只持久化非敏感元数据，密钥仅留当前页面。界面区分配置有效、目录可见和真实调用成功；本次不提供默认触发付费的测试按钮。

## 首版范围

七个协议族：OpenAI Chat Completions、Responses、Images、Anthropic Messages、Gemini GenerateContent、Gemini Interactions、DashScope Multimodal Generation。Chat 图片输出扩展和 Ark Images JSON 编辑作为兼容差异单列，不把服务商数量当协议数量。所有已展示的可选协议必须有实际请求编码、响应解码与工作流测试。同步非流式调用优先；服务端返回异步任务、工具调用或未完成结果时明确停止，绝不重复 POST。需要独立异步持久化和任意模型 input schema 的 Replicate/fal/BFL 等列入后续批次。

## 契约

既有 `modelRoutes` 增加 `accessProvider=custom`，保留准确 `modelId`，新增 `custom` 描述符：版本、connectionId、protocol、baseUrl、认证方式、显式能力和限额。角色之间可复用接入但模型与能力独立。公开任务不含密钥；请求 `apiKeys.custom` 是按 connectionId 包含地址/协议绑定及密钥的序列化凭据容器。准入时只保留实际需要的凭据，执行时再次验证绑定。

未知型号的文本、图片理解、图片生成、直接编辑能力必须显式声明；图片数量、原图字节/总量、尺寸/像素和编码后请求上限不可从名称猜测。平台上限与用户声明的渠道/模型上限取严格值。图片输出参数必须明确支持当前比例和分辨率；固定像素协议使用明确尺寸映射，不静默夹取或切换模型。

## 安全与恢复

Base URL 明确包含版本/网关前缀；只有空路径补默认版本，完整接口地址拒绝并给出中文纠正方式。禁止用户信息、查询参数、fragment、非 HTTPS、非 443、私网/保留 IP、混合 DNS、重定向；自定义公网连接锁定已校验 DNS 地址，TLS 保持原主机校验。已知官方出口继续遵守原出口规则。输出图片下载不携带密钥，逐次校验地址并限制字节。

通用接入参与现有规划、检索、识图、生成、评审、精修。所有实际阶段在发送前检查能力和尺寸；检索图片与上传图片共享阶段预算。无能力时让用户调整配置，禁止隐藏降级。

现有持久化执行器扩展到 custom：发送前登记、成功后保存步骤，重启或响应丢失时停止重复发送；本地校验未发送、明确拒绝、已发送结果未知分别记录。任务凭据仍加密、最长七天，完成后删除；修正密钥只能绑定原地址，不能借恢复改变模型/协议。历史执行版本维持原不确定保护。

## 验收

逐协议请求/响应 fixture，URL/版本拼接、SSRF/DNS rebinding/跳转/凭据绑定、能力和图片预算、单条目录异常/重复ID、中文错误、流式或异步未完成拒绝、地址切换与输入保留、步骤复用和结果未知停止。Core/Web/Mini/Gateway 与共享契约回归、CI、固定镜像和 Pages 发布。Mini 同步消费共享契约并诚实标注原生入口范围，微信平台上传另记。
