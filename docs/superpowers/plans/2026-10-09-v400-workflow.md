# Tuyan 4.0.0 Workflow Implementation Plan

> **For agentic workers:** Use subagent-driven-development for isolated frontend work and independent reviews. Track the integrated backend work here. User explicitly authorized audit then implementation; this is the implementation of the supplied specification.

**Goal:** Extend bounded generation, optional visual assistance and main-model decisions, preserve reference images on revision, make execution and tutorial descriptions accurate.

**Architecture:** Shared workflow policy in packages/api defines integer limits, vision requirements, role selection and descriptions. Keep valid saved model routes as drafts; add `visionMode: 'none' | 'assist'` as an explicit workflow setting rather than inventing a model ID. Core validates before admission, orchestrates observation then main decision and persists candidate progress. Web uses the same policy and negotiates `workflowContractVersion: 1` with Core. Older clients with no visionMode keep their saved vision route and use assistance.

**Tech Stack:** Node 24, TypeScript, React/Vite, shared API modules, existing simulated gateway/Core fixture, browser acceptance.

## Design decisions

- Defaults remain 1 candidate and 1 review; integers only, candidates 1..6, rounds 0..5. Configuration may cap lower but never silently truncate requests. Concurrency is not increased.
- A saved disabled vision route is retained for restoration but never validated as an execution dependency, probed, given credentials or called. `none` is never an API model ID. Unknown main image capability blocks only paths requiring vision.
- Basic generation uses main to form a complete executable plan, then render; no stylist/review. Full adds stylist. SVG review remains text-only; the tutorial must explicitly say no visual review of final SVG. Plot uses main plan/code and worker PNG.
- Uploaded references, generated-image review and refinement require image understanding; library retrieval uses images when independent vision is selected; with no independent vision, a text-only main can use library metadata instead. Independent vision selected always observes first; main decides. All refinement modes plan with main, including direct editing.
- Review count counts attempted review rounds (a failed attempt consumes a round), not internal API calls. An assistance round consists of observer + main decision. Never add paid final checks outside the limit. Persist explicit unreviewed-final status after the last revision or enhancement.
- Use a separate audited reference-generation capability, not mask capability. Pass prior PNG through supported source/reference transport with a full revision prompt. Unsupported or unknown transport logs a visible text-only regeneration reason. No model/provider fallback.
- Persist every candidate result and failure immediately. Definitive candidate failure allows remaining candidates; uncertain paid outcomes retain the existing stop/recovery boundary while preserving completed results.
- Tutorial alone gets documentation-page layout. Workbench/model/settings retain existing structure; add only optional vision choice, required notices, numeric controls and accessible workflow help.
