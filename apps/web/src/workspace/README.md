# Task workspace UI

First implementation of the task-workspace design. These are reusable React components with a development-only local host. The existing production `App` remains the default entry. This directory now implements account task synchronization through the versioned workspace API. Model-library metadata and an encrypted account credential store are integrated; execution transport and its account-scoped credential resolver now reuse the existing job API. The default DEV host uses the local simulator. The explicitly started `tokendance-local.mjs --workspace-real` host permits bounded TokenDance calls and clearly labels real consumption. `WorkspaceAccount` connects login to the existing Better Auth client and account components.

## State invariants

`workspaceState.js` is a UI state machine, not the backend task schema. Task → PNG/SVG branch → generation group → candidate → immutable saved versions. Each branch has a new-generation draft and per-target refinement drafts. Each draft retains independent ordinary/professional settings. A run snapshots the submitted draft and records `parentId` for refinements.

- `BEGIN` reserves a local UI slot; `ACCEPT` moves the empty task to the result layout. Real adapters must obtain server acceptance and resolve ambiguous responses before dispatching it.
- Asynchronous acceptance, result and completion actions carry the original `taskId` and `runId`; attachment completion also carries `path` and `draftTargetId`. Switching tasks cannot redirect a late response.
- `VIEW` only browses. `REFINE` explicitly binds a saved version. Switching paths exits refinement and retains its draft for explicit resumption.
- A result never changes tasks or paths. Manual navigation prevents automatic result following. New versions retain their parent; old versions are not edited in place.
- Failure preserves prior results and restores only an untouched submitted draft. `RESTORE_RUN` refuses to overwrite newer requirements, attachments, mode or settings. It does not execute a retry.
- Requirements reuse is disabled when the destination already contains text, supplements or attachments. Settings-only and supplement-only tasks are not discarded as empty.

## Execution and editing boundary

`workspaceExecution.js` builds existing model-v1 and PNG refinement contracts from an immutable run. It validates exact added model roles, explicit target, original-file dependencies and attachment purposes. `useWorkspaceExecution` waits for task sync, submits once, then queries durable acceptance and jobs across tasks. Unknown responses keep the task occupied. The user can close a request only if the server atomically establishes it has not been accepted; its tombstone rejects a delayed submit. No timeout unlock or automatic resubmit is used.

`workspace-execution.js` in Gateway validates account, Origin, task ownership, exact model-library revision and route binding before resolving credentials in memory. Encrypted account keys are resolved server-side; browser keys are provided only with a real execution request and never synced. The local simulator deliberately skips both decryption and browser-key reads. The existing downstream Gateway/Core ownership, model capability, material and policy checks still apply to real requests.

`WorkspaceSvgEditor` wraps the existing editor and local draft/history store. It preserves original SVG, restores edits by account/task/base-version, and appends a manual child version on save. Continuing AI modification uses the full selected saved source and explicit parent. There is no new blanket data-figure/complex-SVG ban; the existing SVG parser's safety/2 MB limit and data geometry acknowledgement remain. The workspace settings reuse existing native mask and Bria structured-edit controls according to the exact selected model. Required native inputs are validated before submission.

Custom API connections use the current Universal protocol/address validator and capability/limit components. A connection serves multiple exact models. Changed endpoint/protocol/auth requires fresh credentials and capability reconfirmation; model selection never silently adopts a different route. “Added” still does not mean verified invocation. Production-job aggregation/migration, provider-recovery UI and live provider/quality acceptance remain future integration work.

The local host also provides `竖图示例` for testing tall PNG/SVG results. It creates a separate example task and preserves previously loaded examples and drafts.

## Account workspace persistence (2026-10-17)

- `packages/api/src/workspace-sync.mjs` is the version 1 persistence DTO, independent of execution jobs and the model catalog. It allowlists task titles, pin/archive flags, both branches, ordinary/professional settings, requirement drafts, immutable run inputs, candidate/version relationships and result references. Unknown keys (including credentials and original bytes) never enter the stored DTO. Optional settings now include non-sensitive role references, preset connection, figure type, journal selection/version, pipeline, retrieval and image resolution. Prior v1 drafts remain valid.
- Gateway `GET /api/workspace` returns `{ revision, state }`; `PUT` accepts the same revision and a versioned state, returning the new revision. A stale revision returns 409 without overwriting. `POST /api/workspace/results` saves PNG/SVG bytes idempotently and returns a content-based result ID; `GET /api/workspace/results/:id` returns only the current owner's asset. The account header is an expected-identity guard, never authorization; existing server session identity and lifecycle checks authorize every request. Writes require an exact configured Origin. Responses are private/no-store, with no result content or task body logging.
- Result data is stored separately in Mongo `workspaceResults`; snapshots in `workspaceDocuments`; quota accounting in `workspaceQuotas`. Current bounds: 1000 tasks, 2 MB metadata, 10 MB per result, 100 MB result bytes per account. Hitting a bound keeps the local copy and shows an error. Unreferenced uploads count against quota; no automatic destructive cleanup is performed. Normal account deletion removes all three collections' owned records in its existing transaction, and late writes are compensated if the account closes.
- `WorkspaceSyncController` saves locally before attempting synchronization, retries on edits/online/focus/30-second foreground polling and offers manual retry/export. Concurrent changes to different tasks merge. Concurrent content edits to the same task keep a clearly named conflict copy, preserving both branches and histories. Preview navigation and property ordering do not create false conflicts. Failed/expired sessions and switched accounts never redirect queued writes into another account.
- Signing out flushes local writes, then shows guest drafts; account drafts remain in their own local cache and return when that account logs in. They are never automatically copied to guest or a different account. A local-save failure keeps the page/draft and prevents the host from silently unmounting it during logout; export is available for recovery.
- Attachment metadata includes filename, purpose, format, size and SHA-256 only. Merely viewing synced tasks/results, downloading, changing settings or modifying an already saved result does not request old originals. Submitting an operation that references attachments verifies this browser's files first. Missing files show a local re-upload action; bytes must match the recorded digest/size. A different file requires explicit removal/new attachment. Re-upload is browser-only and never starts execution automatically.
- The account runner uses **real existing authentication but local Mongo database `tuyan_workspace_local`**. It does not send workspace data to production. The two-origin browser acceptance uses test accounts and an isolated QA Mongo database, proving separate browser stores rather than claiming a deployed physical-device service. The production host remains unchanged until separately authorized deployment.

Validation: targeted sync/controller/material tests, existing account/workspace component regressions, gateway ownership/CAS/origin/lifecycle tests, production build, and local Chrome two-origin recovery of PNG/SVG results plus missing-original re-upload. Model catalog/channel files and Mini Program are untouched by this change.
